# Подключение существующего Мамута к Gmail и Telegram

Цель: один рабочий бот, без TinyFish и без передачи секретов в чат. Код уже находится в ветке `cloudflare-staging`. Старый Apps Script не отключать, пока новый Worker не готов к переключению.

## Что код уже умеет

- Читать Gmail через REST API, выделять рабочие письма, обрабатывать их в очереди, создавать задачи.
- Читать четыре последних письма в цепочке, извлекать метаданные вложений.
- Готовить локальный ответ, создавать **настоящий** Gmail-черновик, заново читать его и показывать адресата, отправителя, тему и полный текст.
- Отправлять существующий Gmail-черновик исключительно после явной кнопки с одноразовым токеном, отдельного включения `GMAIL_SEND_ENABLED` и повторного сравнения снимка.
- Перед исходящим HTTP-запросом переводить черновик в `SENDING`; после неопределённого ответа Gmail запрещать автоматический повтор.
- При редактировании Gmail-черновика, обнаружении HTML, дополнительных получателей или вложений блокировать автоматическую отправку. Такие письма можно вручную обработать в Gmail.

Это **реализованный код, а не уже подключённый сервис**. Значения секретов в Cloudflare сейчас отсутствуют. Флаги отправки выключены.

## 1. Подготовка базы

В Cloudflare D1 `rahal-mamut-staging` проверь наличие и структуру семи ранее подтверждённых таблиц. Не переигрывай миграции 0001-0003 вслепую, так как их журнал может отличаться от текущих SQL-таблиц.

Применить новые схемы из репозитория:
- `migrations/0004_gmail_draft_delivery.sql` (дополнительные поля и статусы Gmail-черновиков);
- `migrations/0005_google_oauth.sql` (шифрованное хранение refresh token).

Использовать авторизованную консоль D1 или штатный Wrangler. Проверить реальные колонки и индексы. Не удалять существующие записи, не копировать историю почты без согласования.

## 2. Подготовка Google Cloud

1. В существующем или выбранном проекте Google Cloud включить **Gmail API**.
2. Настроить OAuth consent screen, добавить свой Google-аккаунт в test users, если приложение находится в Testing. Учесть правила Google для чувствительных Gmail scopes и возможный срок жизни refresh token в Testing.
3. Создать OAuth 2.0 client типа **Web application**.
4. Указать единственный Authorized redirect URI:

`https://rahal-mamut-staging.alexandr-petrossov.workers.dev/oauth/google/callback`

Нельзя использовать собственный `redirect_uri`, отличный от зарегистрированного. Не публиковать client secret.

## 3. Секреты и переменные Cloudflare

В Settings > Variables and Secrets **только тестового Worker** `rahal-mamut-staging`:

Cloudflare Secrets:
- `GOOGLE_CLIENT_ID` - ID OAuth-клиента.
- `GOOGLE_CLIENT_SECRET` - секрет OAuth-клиента.
- `SETUP_PASSWORD` - случайный пароль владельца длиной минимум 24 символа. Никому не отправлять. Не менять его после авторизации без повторного подключения: ключ шифрования D1 зависит от него и Google client secret.
- `GROQ_API_KEY` - действующий ключ Groq для ответов и анализа.
- Для последующего Telegram-переключения: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_CHAT_ID`. **Использовать существующего бота**, не создавать нового.

Открытые (не секретные) Worker Variables:
- `GOOGLE_OAUTH_REDIRECT_URI=https://rahal-mamut-staging.alexandr-petrossov.workers.dev/oauth/google/callback`
- `GOOGLE_OAUTH_SETUP_ENABLED=true` только на время соединения с Google.
- `GMAIL_ALLOWED_ACCOUNT` при желании задать личный адрес Gmail, который должен быть авторизован. Если указан другой адрес, OAuth отклоняется.

Остальные флаги ПОКА не менять: `GMAIL_POLL_ENABLED=false`, `REMINDERS_ENABLED=false`, `REPLY_PREVIEWS_ENABLED=false`, `GMAIL_DRAFTS_ENABLED=false`, `GMAIL_SEND_ENABLED=false`, `WORKER_EMAIL_NOTIFICATIONS=false`.

Если Wrangler публикует `vars` из `wrangler.jsonc`, убедиться, что флаги и redirect URI сохранены в конфигурации, а секретные значения существуют только как Cloudflare Secrets. Не коммитить содержимое `.dev.vars`.

## 4. Подключить Gmail за один вход

Только после пунктов 1-3 открыть:

`https://rahal-mamut-staging.alexandr-petrossov.workers.dev/oauth/google/start`

Браузер запросит Basic-аутентификацию:
- логин: `admin`;
- пароль: собственный `SETUP_PASSWORD`, созданный на шаге 3.

Затем Google предложит выбрать аккаунт и разрешить `gmail.readonly` (чтение) и `gmail.compose` (черновики/отправка). Доступ предоставляет только владелец аккаунта. Worker проверит состояние OAuth, аккаунт и scope, зашифрует refresh token и сохранит его в D1. Токены не показываются на странице и не пересылаются в чат.

После успешного сообщения на странице немедленно вернуть `GOOGLE_OAUTH_SETUP_ENABLED=false`. Пароль `SETUP_PASSWORD` сохраняется в секретах, поскольку используется для расшифровки токена. При желании можно вместо встроенного подключения добавить `GMAIL_REFRESH_TOKEN` непосредственно как Cloudflare Secret: код поддерживает оба варианта.

## 5. Подключить рабочего бота

Пока старый Apps Script работает, не переключать Telegram webhook.

Далее:
1. После настройки секретов включить `GMAIL_POLL_ENABLED=true` и настроить Cron раз в 5 минут **только когда решено начать реальную обработку почты**.
2. `WORKER_EMAIL_NOTIFICATIONS=false` оставить выключенным, пока старый Apps Script самостоятельно шлёт уведомления, чтобы не создавать дубликатов.
3. `REPLY_PREVIEWS_ENABLED=true` и `GMAIL_DRAFTS_ENABLED=true` разрешить только после применения 0004 и OAuth. Они сами по себе не отправляют email.
4. `GMAIL_SEND_ENABLED=true` включить отдельным сознательным решением, когда проверено создание и полный предпросмотр настоящего Gmail Draft.
5. Перенести состояния и задачи без дублей. Зафиксировать старый webhook URL для мгновенного отката.
6. После согласования переключить **того же** Telegram-бота на `/telegram/webhook`. Не создавать вторую учётную запись или бота.

Вся схема не требует TinyFish и не использует его баланс.

## Где остановиться, если что-то отсутствует

Без Google OAuth нельзя читать Gmail из Cloudflare. Без Telegram Bot Token нельзя принимать и отправлять сообщения от действующего бота. Без Groq Key AI-ответы недоступны. Эти секреты исходный GitHub-репозиторий не содержит, а авторизация Apps Script не переносится автоматически.

Программно можно завершать функциональность, но получить живой результат без этих трёх подключений технически невозможно. Никаких секретов в чат не присылать.
