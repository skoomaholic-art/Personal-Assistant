# Персональный помощник: первый этап - только работа

> **Флаги.** Фактические значения всех переключателей собраны в [docs/FLAGS.md](FLAGS.md): файл создаётся из `config/flags.json` и сверяется тестом с `wrangler.jsonc`. Если текст ниже расходится с этой таблицей, верна таблица.

## Граница данных

- `ASSISTANT_SCOPE=work` является обязательной проверкой в диалоговом маршрутизаторе и в модулях личной почты/календаря.
- Личный Google Calendar, отправка с личного Gmail, приём личных писем и Telegram-рассылка контактам отключены. Существующие Google OAuth токены не удаляются и не распространяются в репозиторий.
- Личный Gmail может использоваться лишь как временный канал **разрешённых компанией вручную пересланных рабочих писем**. Поиск на стадии списка Gmail ограничен рабочим доменом и корпоративным адресатом. Необходимо сохранить согласованную с IT политику обращения с данными.
- Ранее сохранённые персональные записи D1 не уничтожаются: новые выборки рабочего интерфейса ограничены статусами `NEW`, `WORK_REVIEW`, `WORK_OUTLOOK`. Память рабочих поручений и история рабочего чата используют отдельное пространство ключей.
- Содержание Outlook не передаётся в Groq через `src/work-mail.js`, пока `OUTLOOK_AI_ENABLED=false`. Но *текст, который владелец сам пишет боту*, обрабатывается Groq в диалоге: для конфиденциальных корпоративных данных необходимо разрешение компании на использование внешней модели.

## Рабочие действия

1. Читать и сортировать рабочую почту, выделять поручения и новости.
2. Отвечать владельцу текстом и голосом, поддерживать контекст рабочих вопросов.
3. Предлагать и подтверждать задачи; показывать статусы и отчёт; уточнять сроки, переносить и закрывать.
4. Читать рабочий календарь Microsoft 365; предлагать событие и создавать его только после одобрения владельца.
5. Готовить полный текст нового рабочего письма или ответа; показать корпоративный адрес отправителя, получателя и тему, разрешить редактирование, выполнить отправку только после отдельного подтверждения.
6. В дальнейшем: согласованные оповещения владельцу из существующего Telegram-бота; утренний рабочий дайджест.

Существующий Telegram webhook всё ещё закреплён за Apps Script. Настроенные модули Cloudflare не появятся в живом боте до согласованного переключения. Не заводить второго бота.

## Доступ к корпоративному Outlook

Автоматическая внешняя пересылка Outlook блокируется Microsoft 365 с `550 5.7.520`. Не пытаться обходить корпоративные ограничения пересылки. Для доступа Worker требуется **одобренное компанией** приложение в Microsoft Entra ID и согласие пользователя (возможно также администратора):

- Тип приложения: корпоративный single-tenant Web application с конфиденциальным клиентом.
- Redirect URI: `https://rahal-mamut-staging.alexandr-petrossov.workers.dev/oauth/outlook/callback`
- Делегированные разрешения Microsoft Graph: `User.Read`, `Mail.Read`, `Mail.Send`, `Calendars.ReadWrite`, плюс `openid`, `email`, `offline_access`.
- Нужен разрешённый доступ только к собственному корпоративному ящику. Код проверяет возвращённый Microsoft email против заранее указанного рабочего адреса.
- Отдельно согласовать отправку корпоративных данных в Groq и обработку в Cloudflare. Подключение OAuth само по себе **не** означает, что третьей стороне разрешено обрабатывать рабочие письма.
- IT может отказать в части разрешений. В таком случае оставляем соответствующие функции выключенными и не заменяем их обходной пересылкой.

После разрешения компании добавить в Cloudflare Worker только как **Secrets**, без копирования в GitHub или чат: `MS_CLIENT_ID`, `MS_CLIENT_SECRET`; при необходимости указать `MS_TENANT_ID`. Затем владелец может разрешить разовый OAuth (`OUTLOOK_SETUP_ENABLED=true`) по адресу:

`https://rahal-mamut-staging.alexandr-petrossov.workers.dev/oauth/outlook/start`

После успешного входа сразу выключить setup. Только отдельно включать флаги `OUTLOOK_POLL_ENABLED`, `OUTLOOK_CALENDAR_READ_ENABLED`, `OUTLOOK_CALENDAR_WRITE_ENABLED`, `WORK_OUTLOOK_SEND_ENABLED` по одобренным разрешениям. Напоминания включаются только после подключения действующего Telegram-бота.

В личном Gmail остаётся ранее согласованный токен. Не меняйте существующие `SETUP_PASSWORD` и `GOOGLE_CLIENT_SECRET` без переподключения Google: они участвуют в шифровании токена.

## Текущее состояние

Код рабочего режима в ветке `cloudflare-staging`. После просьбы владельца дополнительные ручные прогоны и тесты не запускались. Это **не** подтверждение работы новых модулей в реальном Telegram. Действующий webhook и корпоративные настройки Outlook не менялись. Не обещать фактическую отправку почты, события или уведомлений до подключения корпоративных разрешений и Telegram.
