# Упоминания личного Telegram в существующем помощнике

Текущий путь: MTProto (Telethon) на постоянно работающей машине -> авторизованный HTTPS endpoint существующего Cloudflare Worker -> D1 -> разделы **Задачи / Новости** и при включении уведомлений тот же Telegram-бот. Это не Bot API для чтения личных чатов. `src/telegram-relay.js` отвечает за исходящие сообщения подключённым контактам и не заменяет слушатель.

## Безопасность и подготовка

- В `https://my.telegram.org` создать API application, получить `api_id` и `api_hash`. Код подтверждения Telegram вводится только в собственный локальный терминал при первом запуске Telethon. Никогда не отправлять эти данные и файл `.session` в чат или GitHub.
- Для непрерывной работы нужен отдельный долгоживущий процесс со стойким диском. Cloudflare Worker сам по себе не способен постоянно поддерживать MTProto-соединение. Новый сервер и платные ресурсы **не созданы**.
- Поставить Python >=3.10, установить зависимости: `python -m pip install -r integrations/telegram-mentions/requirements.txt`.
- В окружении этого процесса установить `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_PATH` (по умолчанию `.secrets/telegram-mentions`). Папку `.secrets`, а также файлы `*.session*` Git игнорирует. Сессию держать на личной машине/защищённом томе.
- `python integrations/telegram-mentions/listener.py --list-chats` покажет ID и названия доступных чатов только локально. Не отправлять этот список в публичный чат.
- В Cloudflare Secrets существующего **staging** Worker добавить `TELEGRAM_MENTION_INGEST_SECRET` (длинный случайный ключ), такой же `TG_MENTION_INGEST_SECRET` задать слушателю; `TG_MENTION_INGEST_URL=https://rahal-mamut-staging.alexandr-petrossov.workers.dev/internal/telegram/mention`.
- На стороне Worker установить `TELEGRAM_MENTION_CHAT_IDS` и на стороне слушателя `TG_MENTION_CHAT_IDS`: перечисление одобренных chat IDs через запятую. Значение `*` относится только к групповым чатам; личные сообщения всегда требуют отдельного списка Telegram User ID. По умолчанию без явного выбора ни одно сообщение не принимается. Группам не требуется добавлять бота.
- Проверить состояние D1 и историю миграций, затем однократно применить `migrations/0006_telegram_mentions.sql`. Не проигрывать существующие миграции повторно вслепую.
- Только после этого включить `TELEGRAM_MENTIONS_ENABLED=true` в staging и запустить `python integrations/telegram-mentions/listener.py` на постоянном хосте.
- Для уведомлений использовать уже существующий `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, затем при необходимости установить `TELEGRAM_MENTION_NOTIFICATIONS_ENABLED=true`. Для отправки сообщений владельцу **не нужно** менять Telegram webhook: он остаётся у Apps Script.
- `TELEGRAM_MENTIONS_AI_ENABLED=false` по умолчанию: детерминированная предварительная сортировка без передачи текста в Groq. Можно включить только после согласования обработки содержимого чатов внешним AI. Любая неопределённость классификации - предварительная, пользователь самостоятельно подтверждает важность при взятии задачи в работу.

## Личные переписки по выбору владельца

- Для длинного списка на Windows можно положить `telegram-chat-allowlists.txt` рядом с действующим `TG_SESSION_PATH` (по умолчанию в `.secrets`). Строки `TG_MENTION_CHAT_IDS=` и `TG_MENTION_PRIVATE_CHAT_IDS=` из этого файла имеют приоритет над локальными переменными окружения. Файл хранится вне Git; на Worker отдельно задаются одноимённые значения с префиксом `TELEGRAM_`. Добавление и удаление ID требует только изменения файла и перезапуска прежней задачи.
- При выборе всех чатов из выгрузки включаются также личные переписки и каналы. Это список на момент выгрузки; новые диалоги автоматически в него не попадают. Системный аккаунт Telegram и боты игнорируются слушателем. Метки «работа», «личное» и «прочее» на основании истории общения пока не реализованы; это отдельный этап, и внешний AI-анализ не включён.

- `TG_MENTION_PRIVATE_CHAT_IDS` на Windows и `TELEGRAM_MENTION_PRIVATE_CHAT_IDS` в окружении Cloudflare Worker задаются как одинаковые списки числовых Telegram User ID через запятую. `*` запрещён. Пустой список отключает личные сообщения. Изменяйте список через переменные окружения, без правки кода; после изменения перезапустите существующую задачу `RahalMamut-TelegramMentions`. Не создавайте новую задачу.
- `--list-chats` локально показывает ID, тип и имя диалога. Имя Gulmira само по себе не подтверждает личность; сверяйте ID с карточкой именно нужного контакта. Сессия Telethon остаётся на Windows, повторная авторизация не требуется при сохранении того же `TG_SESSION_PATH`.
- Слушатель читает новые входящие тексты и подписи к фото или документам выбранных людей без обязательного @. Самого владельца и ботов пропускает. Медиа не скачивает. Worker повторно проверяет ID чата и отправителя; `chat_id:message_id` сохраняет дедупликацию. Подпись и тип вложения сохраняются в существующей таблице.
- Предварительная классификация работает локальными правилами: прямые поручения попадают в `tasks` со статусом `NEW`, остальные сообщения в `telegram_mentions` как `NEWS`. Важность окончательно выбирается при принятии задачи. Личные тексты не передаются в Groq даже при включённом флаге AI для групп. Уведомления владельцу отправляются обычным сообщением без кнопок при действующем webhook Apps Script. Коллегам ответов нет.

## Поведение

Слушатель читает только новые доступные ему сообщения, в которых есть `@skoomaholic`, Telegram отмечает аккаунт напрямую, либо сообщение является ответом на сообщение владельца. Вложенные изображения и документы не скачиваются. Сообщения из недоступных и секретных чатов не считываются. Одинаковые `chat_id + message_id` дедуплицируются. Чат и автор подписываются к записи, исходная ссылка открывается там, где Telegram поддерживает её.

Записи с явной просьбой сохраняются в `tasks` как `NEW` с предварительной важностью. При нажатии «Взять в работу» владелец выбирает важность; остальные упоминания сохраняются в `telegram_mentions` как `NEWS` и появляются в существующем меню «Новости». В исходных чатах ничего не отправляется, исходные сообщения не изменяются. Отдельная пересылка в личные сообщения бота включается только флагом уведомлений.

## Что не выполнено автоматически

Авторизация личного Telegram, установка секретов, применение SQL, выбор охватываемых чатов, запуск постоянно работающего слушателя и публикация кода в Cloudflare требуют отдельного доступа к среде и/или действий владельца. Изменение GitHub само по себе не запускает приём упоминаний. Существующий bot webhook оставлен без изменений.

Пока webhook принадлежит Apps Script, входящие уведомления от Worker отправляются **без кнопок**: Apps Script не знает новых `mention:view` callback. Флаг `TELEGRAM_MENTION_WORKER_CALLBACKS_ENABLED=true` допускается только после отдельно согласованного переключения существующего webhook на Worker. Не включать его сейчас.
