# Персональный помощник | Cloudflare migration

> **Текущий этап: только работа.** Параметр `ASSISTANT_SCOPE=work` отключает личный Gmail, личный календарь и личные действия. В Gmail разрешён только поиск рабочих писем, пересланных с рабочего адреса; прямой Outlook остаётся неавторизованным до согласования компании. Составление рабочих писем и встреч выполняется через рабочий Outlook, без отправки из личного Gmail. Рабочая память и чат отделены от личных. Подробно: [docs/WORK_ONLY.md](docs/WORK_ONLY.md).


> **Флаги.** Фактические значения всех переключателей собраны в [docs/FLAGS.md](docs/FLAGS.md): файл создаётся из `config/flags.json` и сверяется тестом с `wrangler.jsonc`. Если текст ниже расходится с этой таблицей, верна таблица.

Ветка `cloudflare-staging` содержит **тестовый** сервер. Рабочий бот остаётся на Google Apps Script; его webhook, Gmail, таблицы и триггеры не изменены. Второго бота нет.

## Исходники и компоненты

- `legacy/Code.gs`, `legacy/Storage.gs`, `legacy/Webhook.gs`, `legacy/MailActions.gs` - копии исходных скриптов v1.1 как reference, **не запускаются** в Cloudflare.
- `src/router.js` - команды/кнопки и чистые функции.
- `src/task-dialog.js` - естественный диалог, уточнения, подтверждение создания задачи, списки и отчёты, закрытие и мягкое удаление. Действия в D1 выполняет код, а не модель.
- `src/calendar.js` - личный Google Calendar и рабочий Outlook: чтение повестки, черновики событий, подтверждённое добавление с защитой от повторной отправки. Личный календарь требует отдельного согласия Google; корпоративный пока заблокирован флагом до согласования.
- `src/personal-mail.js` - личный Gmail: свободный черновик, ответ на выбранное письмо, полный предпросмотр, редактирование и отправка только после отдельного подтверждения.
- `src/telegram-relay.js` - одноразовые приглашения получателей; бот пишет от своего имени только тому, кто добровольно открыл бот, после явного подтверждения владельца.
- `src/memory.js` - сохраняемые только с подтверждением заметки; их можно просмотреть и удалить.
- `src/brief.js` - сводка почты, задач и доступных календарей; утренние сообщения включаются только после переключения одного существующего бота.
- `src/outlook.js` - Microsoft Graph OAuth, чтение рабочей почты, календарь; все флаги корпоративного доступа выключены до разрешения компании.
- `src/news.js` - актуальные заголовки из публичного RSS без платного API.
- `src/miniapp.js` - встроенная в Telegram панель задач, почты, календаря и памяти с проверкой подписи Telegram и идентификатора владельца.
- `src/voice.js` - получение голосовых Telegram владельца и распознавание Whisper через Groq; аудиофайлы не сохраняются.
- `src/worker.js` - Telegram webhook, очередь, D1, Groq, read-only диагностика.
- `src/telegram-cutover.js` - страница владельца для переключения существующего бота на Worker и отката на Apps Script; порядок действий в [docs/CUTOVER.md](docs/CUTOVER.md).
- `src/admin.js` - защищённое паролем подтверждение Google/Groq, число обработанных писем и статус последней проверки без доступа к содержимому почты.
- `src/gmail.js` - Gmail REST: чтение писем и цепочек, метаданные вложений, рабочий фильтр, Groq-анализ, задачи и дедупликация. Для обработки писем достаточно разрешения `gmail.readonly`.
- `src/reminders.js` - выбор задач и защита от повторных Telegram-уведомлений с D1 claim до отправки.
- `src/drafts.js` - локальные черновики. `src/gmail-compose.js` - создание настоящего Gmail Draft, полный предварительный просмотр, проверка адресатов и корпоративного alias, отдельное подтверждение и однонаправленный статус отправки. `GMAIL_DRAFTS_ENABLED` и `GMAIL_SEND_ENABLED` по умолчанию выключены.
- `src/google-oauth.js` - вход Google для владельца с CSRF-защитой и шифрованным refresh token в D1. Запускается только при отдельном включении. `migrations/0005_google_oauth.sql` применена в D1, Google подключён с согласия владельца. `0004_gmail_draft_delivery.sql` ещё не подтверждена в D1. Обработка новых писем включена отдельно через Cron.
- `test/` - синтетические тесты без доступа к Gmail и Telegram, в том числе с настоящим SQLite по схеме D1. Проверяются конкурирующие обработчики, повторы Telegram, откат транзакции письма и задачи.

## Новая модель работы

Основной интерфейс - существующий Telegram-бот. Сообщения и голосовые преобразуются в намерение; действия идут через отдельные API-модули. Внешняя отправка письма, сообщения контакту и создание встречи требуют подтверждения конкретного черновика. Отложенные напоминания и дневные сводки используют Cron и D1. Подключения сторонних сервисов требуют отдельных OAuth-разрешений. Mini App работает только после аутентификации через Telegram.

Личный Gmail подключён как технический канал, но `ASSISTANT_SCOPE=work` запрещает обработку личной переписки и отправку с личного адреса. В рабочие разделы допускаются только письма с подтверждённым корпоративным происхождением. Рабочая почта без разрешения на внешний AI попадает в «Новости» только по очевидному информационному заголовку, остальные сообщения требуют решения владельца. Совместный Telegram/почтовый список задач, новостей и записей на разбор реализован в коде staging. Действующему Telegram-боту новая версия не подключена.

ВНИМАНИЕ: старый Telegram webhook и Apps Script не переключены. У Cloudflare нет подтверждённого доступа к корпоративному Outlook. Рабочий Outlook требует разрешения компании и отдельного OAuth. Календарь Google требует отдельного согласия: [войти в Google Calendar](https://rahal-mamut-staging.alexandr-petrossov.workers.dev/oauth/google/calendar/start). Для готового UI после переключения: [Mini App](https://rahal-mamut-staging.alexandr-petrossov.workers.dev/app).

## Запуск тестов

Node.js 20+:

```bash
npm run check
npm test
```

[Тестовый Worker](https://rahal-mamut-staging.alexandr-petrossov.workers.dev/health)
| [D1 health](https://rahal-mamut-staging.alexandr-petrossov.workers.dev/health/db)

`npm run check` проверяет синтаксис всех модулей в `src`, `scripts` и `test`. В CI проверка и тесты запускаются на каждый pull request и push; публикация Worker из ветки `cloudflare-staging` выполняется только после их успешного прохождения. Это **не** заменяет живую проверку Gmail/OAuth/Telegram и не доказывает скорость реального бота.

Диалоговые сценарии проверяются на синтетических сообщениях через настоящий D1-совместимый SQLite. Реальные Telegram-тесты невозможны без подключения существующего токена/webhook; старые задачи из Apps Script/Sheets в D1 пока не перенесены. Рабочую корпоративную почту пересылать без разрешения компании нельзя.

## Будущая безопасная настройка

1. Все семь нужных таблиц D1 подтверждены живыми `/health/db` и `/health/features`. Проверить соответствие колонок и индексов, затем состояние журнала Wrangler migrations. Не повторять миграции без предварительной проверки, не выполнять DROP/DELETE и не импортировать корпоративную почту без согласования.
2. Выполнить инструкцию `docs/CONNECT.md`: Google OAuth Web client, Gmail API, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SETUP_PASSWORD` как Cloudflare Secrets. Через защищённый вход владельца получить Gmail consent (`gmail.readonly` и `gmail.compose`); refresh token сохранится зашифрованным в D1. Для ручной установки Cloudflare Secret `GMAIL_REFRESH_TOKEN` также поддерживается. Никогда не отправлять секреты в чат и GitHub.
3. Cron Trigger `*/5 * * * *` и `GMAIL_POLL_ENABLED=true` добавлены в `wrangler.jsonc`. Проверить фактическое выполнение на опубликованном Worker через защищённый `GET /admin/connections` после первой пятиминутки. Без подтверждённого живого статуса не считать почту реально обработанной.
4. Отдельно проверить дедупликацию новых писем, задачи, историю, уведомления и откат. На время тестов `WORKER_EMAIL_NOTIFICATIONS` оставлять выключенным, потому что исходный Apps Script уже шлёт уведомления.
5. Перед включением напоминаний и локальных черновиков сверить реальные схемы таблиц с миграциями 0002 и 0003 и провести синтетические end-to-end проверки.
6. Только при достигнутом функциональном соответствии и после замеров согласовать переключение **одного существующего** Telegram webhook на Worker с заранее зафиксированным старым URL для отката. Ключи не публиковать.
7. Код создания и отправки существующего Gmail Draft добавлен. Он **не активирован**: для включения нужны миграция 0004, OAuth с `gmail.compose`, корпоративный send-as alias и отдельное явное разрешение. HTML, вложения, дополнительные получатели и изменённые Gmail-черновики автоматически не отправляются. Установить `GMAIL_SEND_ENABLED=true` только после согласования запуска.

**Важно:** GitHub хранит код, а секреты Google/Groq находятся в Cloudflare Secrets. Письма анализируются Groq только после проверки рабочего адресата/отправителя. Отправка Gmail и уведомления существующему Telegram-боту отключены.
